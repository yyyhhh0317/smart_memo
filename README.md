### 智能知识内化与检验系统：项目需求与制作方案说明文档

#### 一、 项目概述
本项目旨在打造一款基于大语言模型（LLM）的智能学习辅助工具。系统核心目标是帮助用户高效地对复杂知识进行“背诵”与“深度理解”。通过自动化解析用户上传的多种格式资料，系统能够智能生成针对性的检验任务，以“主动回忆”为核心机制，提升用户的学习效率与知识留存率。

#### 二、 核心需求分析
基于您的规划，本项目的核心业务需求可拆解为以下三大模块：

1. 多模态知识导入模块
   - 支持格式：图片、Word、PPT 等常见文档格式。
   - 智能分类：系统需自动识别并提取文档内容，将其精准划分为“文本类”（侧重记忆与复述）和“知识类”（侧重逻辑与深度思考）。

2. 文本类检验生成模块
   - 关键词填空：将原始知识转化为纯文本，精准识别核心关键词，并随机将其转换为填空题供用户作答。
   - 框架挖空：对长文本进行总结与梳理，提炼出整体知识框架，并在框架的关键节点处进行挖空测试。
   - 大纲复述：生成简略版的大纲结构，引导用户脱离原文，进行自主复述与内容重构。

3. 知识类检验生成模块
   - 深度思考问答：针对知识类内容，生成具有启发性、值得深度思考的问题。
   - 严格边界控制：所有生成的问题及其答案推导，必须严格限制在用户上传的内容范围内，严禁引入外部知识或产生AI幻觉。

#### 三、 技术选型与架构方案
结合您的技术栈（Python + HTML/CSS/JS），推荐采用以下现代化、高扩展性的架构：

1. 后端服务层 (Python)
   - 核心框架：FastAPI。具备高性能异步处理能力，完美契合大模型接口的流式响应（SSE）需求。
   - 文档解析：使用 `python-docx` (Word)、`python-pptx` (PPT) 进行结构化文本提取；接入 PaddleOCR 或云厂商 OCR API 处理图片文字识别。
   - AI 引擎：对接国内主流大模型 API（如通义千问、DeepSeek等），通过精心设计的 Prompt 工程控制输出格式（强制 JSON 结构化输出）。

2. 前端交互层 (HTML/CSS/JS)
   - 基础方案：原生 HTML5 + CSS3 + Vanilla JS。
   - 进阶建议：若后续交互复杂（如复述录音、动态填空高亮），建议平滑过渡至 Vue.js 或 React 框架，配合 TailwindCSS 提升开发效率与界面美观度。

3. 数据存储层
   - 轻量级起步：初期可使用 SQLite 存储用户资料与检验记录；后期可无缝迁移至 PostgreSQL。

#### 四、 后续制作与实施路线
为确保项目稳步落地，建议采用敏捷开发模式，分四个阶段推进：

阶段一：核心闭环验证（MVP阶段）
- 目标：跑通“纯文本输入 -> AI生成检验题 -> 前端渲染”的最小链路。
- 任务：搭建 FastAPI 基础环境；编写并调优“关键词填空”与“知识类提问”的 Prompt；实现基础的前端页面与接口对接。

阶段二：多模态解析与分类引擎
- 目标：实现完整的多格式文件上传与智能分类。
- 任务：集成 Word/PPT/图片解析库；开发文本清洗与预处理逻辑；实现“文本类/知识类”的自动分类算法。

阶段三：高阶交互与体验打磨
- 目标：实现框架挖空、大纲复述等复杂交互。
- 任务：开发前端富文本编辑器或录音组件；实现“复述内容”与“原文”的语义比对打分功能；接入流式输出（SSE）优化等待体验。

阶段四：产品化与部署上线
- 目标：形成可交付的完整产品。
- 任务：增加用户鉴权与历史记录管理；引入错题本与艾宾浩斯记忆曲线复习机制；完成云服务器部署与域名配置。

#### 五、 关键风险与应对策略
- AI 幻觉风险：在“知识类”提问中，大模型可能发散思维。应对策略：在 System Prompt 中增加强约束指令，并要求大模型返回问题时附带“原文出处引用”，前端进行校验。
- 解析格式错乱：复杂 PPT 或图片提取的文本可能缺乏逻辑。应对策略：增加一道“文本结构化清洗”的 AI 预处理工序，将碎片化文本重组为连贯段落后再进行检验题生成。
